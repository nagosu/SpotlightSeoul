# Phase 7 — 인증/토큰/401 복귀 동선(엔트리포인트)

## 목표(Why)
- Bearer 인증이 필요한 API(좋아요/북마크/내 북마크)를 안정적으로 지원하기 위해 **토큰 저장/주입/만료(401) 처리**를 표준화합니다.
- 401 발생 시 “로그인 유도 + 원래 하려던 작업으로 복귀(returnTo)”를 일관되게 구현합니다.

## 범위(Scope)
- 토큰 저장/조회/삭제 정책(로그아웃 포함)
- 401 엔트리포인트 정책(라우팅/returnTo 보존/복귀)
- “보호 기능”의 동작 정의(비로그인 상태에서 토글/내북마크 접근 등)

## 근거(Evidence)
- `frontend/docs/FRONTEND-UPGRADE-PHASES.md` 2.4(인증 상태/401 엔트리포인트), 4.3(401 정책 점검)
- Bearer 필요 API: 1장(인증 요약), 3.5/3.6(좋아요/북마크)

## 선행조건(Dependencies)
- Phase 6(로그인/회원가입 동작), Phase 3(HTTP 레이어), Phase 5(UX 상태)

## 작업 체크리스트(아주 상세)
### A. 토큰 저장 위치 결정(원문 2.4)
- [ ] 기본 정책을 정합니다(원문: “기본: 브라우저 저장소. 보안 리스크는 문서로 명시”).
  - 옵션 예시: `localStorage`, `sessionStorage`, 메모리(in-memory)
- [ ] 선택한 저장 방식의 장단점을 문서에 3줄로 명시합니다.
  - 예: localStorage는 새로고침/탭 종료에도 유지되지만 XSS 리스크가 있음
- [ ] 토큰 저장/조회/삭제 API(함수 형태)를 문서로 고정합니다.
  - 예: `setAccessToken(token)`, `getAccessToken()`, `clearAccessToken()`

### B. Authorization 헤더 주입 규칙(원문 2.2)
- [ ] 토큰이 있을 때만 `Authorization: Bearer <token>`을 붙입니다.
- [ ] 토큰이 없을 때는 인증이 필요한 API 호출 시 401이 날 수 있으므로, 호출 전에 UX로 “로그인 유도”를 할지 정책을 정합니다.

### C. 401 처리 정책(원문 2.4, 4.3)
- [ ] 401이 오면 다음을 수행합니다.
  - 토큰 제거(또는 만료 처리)
  - 로그인 화면으로 이동
  - `returnTo`(원래 위치) 보존
- [ ] `returnTo` 표현 방식을 고정합니다.
  - 최소 변경 권장: 로그인 페이지 URL에 `?returnTo=/원래경로`를 붙임
  - 주의: 상세/검색 파라미터 등 query까지 포함할지 규칙을 명시합니다.
- [ ] 로그인 성공 후 복귀 규칙을 고정합니다.
  - `returnTo`가 있으면 그 경로로 이동
  - 없으면 홈으로 이동

### D. “원래 하려던 동작” 복귀(원문 4.3)
- [ ] 단순 경로 복귀만으로 충분한지 판단합니다.
  - 예: “내 북마크 보기”는 경로 복귀만으로 OK
  - 예: “좋아요/북마크 토글”은 사용자가 다시 클릭해야 할 수도 있음
- [ ] 최소 기준으로 다음을 문서에 명시합니다.
  - 로그인 유도 후 복귀했을 때, 사용자가 **재시도할 수 있는 UI**가 그대로 보인다.
  - (선택) 토글류는 “의도했던 액션”을 저장했다가 로그인 직후 자동 재시도하는 전략을 문서에 선택지로 둔다.

## Definition of Done(DoD)
- 비로그인 상태에서 좋아요/북마크/내 북마크를 시도하면 로그인 유도 → 로그인 후 복귀 흐름이 끊기지 않습니다.
- 401이 발생해도 앱이 크래시하지 않고, 토큰 정리 및 복귀 동선이 일관되게 동작합니다.

## 검증 방법
- [ ] 토큰 없는 상태에서 `PUT /festivals/{id}/like` 또는 `PUT /festivals/{id}/bookmark`를 시도 → 로그인 유도 → 로그인 후 상세로 복귀되는지 확인합니다.
- [ ] 토큰을 일부러 잘못 넣어 401을 유발 → 토큰이 제거되고 로그인 화면으로 이동하는지 확인합니다.

## 주의/함정
- 401 처리를 “여기저기” 분산하면, 어떤 경우에는 토큰이 남고 어떤 경우에는 지워지는 식으로 일관성이 깨집니다. 401 엔트리포인트는 한 곳에 모아야 합니다.
