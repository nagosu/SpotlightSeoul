# Phase 15 — 내 주변 `GET /festivals/near`(권한 UX + 거리 표시)

## 목표(Why)
- 사용자 위치 기반으로 주변 축제/공연을 보여주는 기능을 구현합니다.
- 위치 권한(허용/거부/실패) 시나리오에 따라 UX가 깨지지 않도록 폴백을 제공합니다.

## 범위(Scope)
- API: `GET /api/v1/festivals/near?lat=&lot=&radius_km=&status=&page=&size=` (200)
- `lat`(위도) / `lot`(경도) 파라미터명 고정(Phase 1 규칙)
- 응답의 `distance_km`는 프론트에서 `distanceKm`로 사용(Phase 4)

## 근거(Evidence)
- `frontend/docs/FRONTEND-UPGRADE-PHASES.md` 3.8(내 주변), 2.2 주의(lat/lot)

## 선행조건(Dependencies)
- Phase 8(Query), Phase 5(상태 UX)

## 작업 체크리스트(아주 상세)
### A. 위치 권한 UX 설계(원문 3.8)
- [ ] 권한 요청 전에 안내 문구를 표시할지 결정합니다(사용자 놀람 방지).
- [ ] 권한 허용: 위치 획득 → near API 호출 → 결과 표시
- [ ] 권한 거부: 폴백 UI 제공
  - 예: “위치 권한이 필요합니다” + 권한 설정 안내 + 기본 목록/검색으로 유도
- [ ] 위치 획득 실패/타임아웃: 재시도 버튼 제공

### B. 파라미터 규칙 고정(중요)
- [ ] `lat`/`lot` 파라미터명을 사용합니다(Phase 1 규칙).
- [ ] `radius_km` 기본값을 정합니다(예: 3km/5km).
- [ ] `status/page/size`는 목록과 동일 규칙을 적용합니다.

### C. 거리 표시 UX
- [ ] 응답의 `distanceKm`를 UI에 표시합니다(예: “2.1km”).
- [ ] 거리 표시의 소수점 처리 규칙을 문서로 고정합니다(예: 소수점 1자리 반올림).

### D. 상태 UX 적용
- [ ] 로딩: 위치 획득 로딩 + API 로딩 구분(문서로 명시)
- [ ] 오류: 위치 오류 vs API 오류 메시지 구분(가능하면)
- [ ] 빈 결과: 반경/필터 조정 안내 제공

## Definition of Done(DoD)
- 권한 허용/거부 시나리오별로 화면이 깨지지 않고, 정상 시 거리순 목록이 표시됩니다(원문 DoD).

## 검증 방법
- [ ] 브라우저 위치 권한을 허용/거부로 각각 테스트합니다(원문 3.8 검증).
- [ ] Swagger UI로 동일 lat/lot/radius_km 요청 결과와 프론트 표시를 비교합니다.

## 주의/함정
- `lot`를 `lng`로 착각하면 API가 정상 동작하지 않습니다.
- 권한 거부 시나리오를 고려하지 않으면 기능이 “아예 안 되는 것처럼” 보일 수 있습니다. 폴백 UX는 필수입니다.
