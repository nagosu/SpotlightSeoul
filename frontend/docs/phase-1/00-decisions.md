# [P1-DEC] Phase 1 정책 결정(필수)

> 목적: Phase 1 작업이 “중간에 방향이 갈라져서” 재작업되지 않도록, 최소한의 정책을 먼저 확정합니다.

---

## [P1-DEC-01] API baseURL 정책

- **결정**: `VITE_API_BASE_URL`로 관리(Dev/Staging/Prod 분리)
- **DoD**
  - 프론트 코드에서 `http://localhost:8080` 하드코딩 호출이 제거됩니다.
  - 로컬/운영 전환이 “코드 수정 없이” 환경 변수로만 가능합니다.

---

## [P1-DEC-02] 응답 snake_case 처리 정책

- **배경**: OpenAPI 응답 키가 snake_case가 기본(`festival_like`, `total_page_num` 등)
- **선택지**
  - **A. snake_case 그대로 사용**
    - 장점: 변환 로직/오버헤드 최소
    - 단점: UI 코드에서 snake_case를 계속 다뤄야 함
  - **B. camelCase로 변환하여 사용**
    - 장점: UI 코드 가독성 향상
    - 단점: 변환 함수/타입/테스트 비용 증가(혼재 방지 필요)
- **DoD**
  - “어디에서 변환하고(네트워크 레이어/도메인 레이어), 어디까지 변환하는지(깊이/배열 포함)”가 문서/코드로 고정되어 혼재가 없습니다.

---

## [P1-DEC-03] 타입 전략(최소 기준)

- **선택지**
  - **A. 수동 타입 정의**(필요한 응답만)
  - **B. OpenAPI 기반 부분 자동 생성**(도구/파이프라인 도입)
- **Phase 1 최소 목표**
  - “핵심 응답 2~3개”는 타입으로 고정합니다(목록/상세/검색 등).
