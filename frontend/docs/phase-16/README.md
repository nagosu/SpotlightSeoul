# Phase 16 — 지도(Naver) 키/env화 + 스크립트 로딩 단일화

## 목표(Why)
- 네이버 지도 스크립트 로딩 방식을 “하나”로 단일화하여 중복 로드/초기화 타이밍 버그를 제거합니다.
- 지도 clientId를 코드에 하드코딩하지 않고 **env로 분리**합니다.

## 범위(Scope)
- `index.html` 전역 로드 vs 런타임 로드 중 하나를 선택해 단일화
- `VITE_NAVER_MAP_CLIENT_ID`(예시) 등 env 분리
- 지도 컨테이너 렌더 타이밍 보장 + 실패/좌표 없음 처리

## 근거(Evidence)
- `frontend/docs/FRONTEND-UPGRADE-PHASES.md` 3.9(지도)
- `frontend/docs/AS-IS.md` 근거: 전역 로드 + 컴포넌트 동적 로드가 공존, clientId 하드코딩 존재

## 선행조건(Dependencies)
- Phase 2(env 규칙), Phase 10(상세에서 지도 조건부 렌더)

## 작업 체크리스트(아주 상세)
### A. 로딩 방식 단일화 결정(원문 3.9)
- [ ] 옵션 A: `index.html`에서 전역 스크립트 로드
  - 장점: 단순, 최초 1회 로드
  - 단점: 지도 기능을 쓰지 않아도 초기 로드 비용 발생
- [ ] 옵션 B: `MapInformation`에서 런타임 로드(필요할 때만)
  - 장점: 필요할 때만 로드(성능)
  - 단점: 초기화/컨테이너 타이밍 관리 필요
- [ ] 선택한 방식을 문서에 고정하고, 다른 방식 코드는 제거합니다.

### B. clientId env 분리(원문 3.9)
- [ ] 지도 clientId는 env(`VITE_*`)로만 받습니다.
- [ ] README에 “키/토큰을 채팅에 붙여넣지 않는다”는 운영 원칙을 명시합니다.
- [ ] `.env.local` 등 파일을 커밋하지 않는 정책을 유지합니다.

### C. 컨테이너 렌더 타이밍 보장(원문 3.9)
- [ ] 지도 초기화는 반드시 지도 컨테이너 div가 DOM에 존재한 뒤에 수행합니다.
- [ ] 상세에서 좌표가 없을 때는 지도 자체를 렌더하지 않습니다(Phase 10).

### D. 실패/좌표 없음 대체 UI
- [ ] 스크립트 로드 실패: “지도를 불러오지 못했습니다” + 재시도(선택)
- [ ] 좌표 없음: 지도 대신 텍스트/주소만 표시

## Definition of Done(DoD)
- 지도 스크립트는 한 번만 로드되고, 키가 코드에 하드코딩되어 있지 않으며, 실패해도 상세 화면이 죽지 않습니다(원문 DoD).

## 검증 방법
- [ ] 상세 페이지에서 지도 영역이 정상 표시되는지 확인합니다.
- [ ] 네트워크 차단/키 누락 등으로 로드 실패를 유발해도 상세 화면이 깨지지 않는지 확인합니다.

## 주의/함정
- 로딩 방식이 둘 다 남아 있으면 “중복 로드/초기화 순서 경쟁”이 발생합니다. 반드시 하나로 단일화해야 합니다.
